# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

lobzique is a Ruby gem with a Rust extension that reimplements the subset of Nokogiri's HTML API that Rails and its HTML dependencies (Loofah, rails-html-sanitizer, rails-dom-testing, Action Text) use, so libxml2 drops out of Rails' path. It is early: the Rust code is still a `hello` placeholder. `plan.md` holds the goal, scope, phases and the design decisions (namespace and facade, XPath subset, HTML4 names parsing as HTML5, XML deferred); read it before any design work.

## Commands

Ruby 3.3 (`mise.toml`, `.ruby-version`); CI also tests 3.4 and 4.0.
`mise.toml` wraps the rake and cargo commands as tasks (`mise tasks` lists them):

```sh
mise run check            # compile, Ruby tests, standard, core crate tests
mise run test             # compile + Minitest
TEST=test/test_lobzique.rb TESTOPTS="-n test_name" mise run test   # one Ruby test
mise run test:rust        # core crate tests; one test: cargo test -p lobzique-core <name>
mise run lint             # standard (lint:fix to autofix)
mise run test:gc-stress   # dev build with rb-sys gc-stress + GC.stress per test
mise run miri             # nightly
mise run asan             # nightly, core crate only
mise run fuzz <target> [-max_total_time=60 ...]   # nightly + cargo-fuzz; targets in fuzz/fuzz_targets/
mise run progress         # how much of inventory/contract.yml is defined (progress:missing lists gaps)
mise run fixtures:verify  # checksum test/fixtures, as CI does
mise run differential [--corpus crawl] [--only REGEXP]   # compare with Nokogiri::HTML5 (plan.md decision 6)
mise run crawl:fetch      # download the pinned Common Crawl sample into tmp/crawl/
```

`test:gc-stress` leaves a slow debug build in `lib/`; run `mise run compile` afterwards. The README has the full table of safety checks (Miri, ASan for Rust and Ruby, GC.stress, fuzzing) and their local setup.

## Architecture

- `crates/lobzique-core`: all library logic. Must not depend on Ruby (magnus/rb-sys), so Miri, ASan and fuzzers run it without a Ruby VM. The plan is to keep it free of `unsafe` (an index-based arena DOM).
- `ext/lobzique`: magnus bindings only, built by rb_sys (`extconf.rb`) into `lib/lobzique/lobzique.{bundle,so}`. The `gc-stress` Cargo feature is what `rake test:gc_stress` turns on.
- `lib/`: Ruby side. `Lobzique::` is meant to mirror Nokogiri's class tree (`XML::Node`, `XML::NodeSet`, `HTML5::Document`, …) with Nokogiri's names, constants and hierarchy, because callers use `is_a?`/`case`, subclass the document classes, and compare `Node::*_NODE` constants. A separate `nokogiri` facade gem is planned on top.
- `fuzz/`: its own Cargo workspace (nightly-only; the main workspace builds on stable). Every entry point that takes untrusted input needs a target in `fuzz/fuzz_targets/` plus a `[[bin]]` in `fuzz/Cargo.toml`; CI fuzzes each for 60s.

## Test fixtures and inventory

- `test/fixtures/` is third-party upstream data (html5lib-tests, WPT, DOMPurify, and Nokogiri/Loofah/Rails Minitest files) kept byte-for-byte and checksum-verified in CI. Never edit it by hand: change `test/fixtures/sources.yml` and run `script/fetch_fixtures`. The `.rb` files there are contracts to port, not tests; Rake, standard and `CLEAN` all exclude the directory. `test/fixtures/README.md` describes each format. Prefer this existing data over synthetic test inputs for anything larger than a unit test.
- `inventory/` is the API contract from phase 1. `contract.yml` and `summary.md` are generated by `script/inventory/aggregate.rb`; scope decisions go in `inventory/scope.yml`. `inventory/README.md` explains the method and how to regenerate. `inventory/raw/` (~2 GB of checkouts and traces) is gitignored.
- `test/differential/` is the harness that runs Nokogiri::HTML5 and lobzique on the same inputs. Its corpora are `test/fixtures` and a Common Crawl sample that is pinned in `crawl.yml` and never committed. Accepted differences go in `known.yml` with a reason. A divergence found on a crawled page becomes a small hand-written case, not a copy of the page.
- The repo is public: evidence in the inventory, plan and tests comes only from public gems and apps (`script/inventory/apps.tsv`). Don't add anything about private apps.

## Code style and comments

Leave comments only for non-obvious decisions. Comments should be terse. They are read together with code, and good names for variables and methods are better than whole sentences in comments.
